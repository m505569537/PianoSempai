# 0001: M7 AI 助教 Grill 决议（多服务商故障转移架构）

## 状态
已确认（2026-09-20 用户 OK）

## 背景
P3 开工半小时实证结论：用户现有方舟 key（coding 套餐）在标准 /api/v3 入口身份有效，
但账号下所有标准 doubao 模型均 ModelNotOpen；coding 入口仅 Anthropic 协议、模型名为
代理别名。故模型接入从"写死火山方舟单 key"改为多服务商 × 多模型故障转移链，
任一服务商可用即可正常工作，供应商开通/失效均不阻塞。

## 决策内容（17 项）

### 一、多服务商体系
- Q1：预设模板（火山方舟/百炼/DeepSeek 等，选模板只填 key、base_url 自带）
  +「OpenAI 兼容」自定义兜底（手填 base_url + key）
- Q2：只配一条链，链上全为多模态模型；纯文字问题走同链但不带附件（不做双链管理）
- Q3：静默故障转移，中间失败不打扰，全链失败才报错；设置页诊断记录实际命中模型与失败原因
- Q4：粘住上次成功模型，失败才沿链降级；定时试探高优先级模型恢复

### 二、三个入口
- Q5：会话中「问 Neko」FAB → 底部半屏问答抽屉，自动预填曲目/小节/take 结论，不跳页
- Q6：报告页具体错误条目旁「问 Neko」小按钮 → 同一抽屉并锁定该条，答案可一键钉到错误点
- Q7：全局自由问答入口放曲库页顶部，带课程进度+历史 take 摘要；不新增 tab（底部 5 tab 铁律）
- 三入口统一复用同一套底部问答抽屉组件

### 三、上下文 / 视频 / 降级
- Q8：强制引用数据（第几次 take、第几小节、偏差 ms）；上下文无数据时明说「我看不到 xx」，禁止空谈
- Q9：视频上传前弹确认「将发送 X 秒视频到 [实际服务商名]」，可取消；纯 MIDI/文字问题永不传视频
- Q10：离线时文字问题本地组 prompt 存草稿、联网一键重发；视频问题进待发队列不丢

### 四、资产 / 通知 / 月报
- Q11：全部问答自动沉淀为「练琴笔记」，可钉到曲目、全文搜索、可删除
- Q12：每周日晚一条合并通知（本周观察 + 一个小建议），本周没练琴不发，设置可关
- Q13：月报 AI 起草从 M8 提前到 P3，默认开可关，用户改后存档

### 五、权限 / 工程
- Q14：AI 建议带动作按钮（如「回退拜厄 40」），用户点才执行并留痕；AI 永不碰门禁/阈值/过关
- Q15：每个服务商带「测试连接」按钮，实时验证服务商+模型可用性
- Q16：分两步落地——M7.1 服务商链+问答抽屉+上下文+笔记；M7.2 周日通知+月报起草+视频裁切上传
- Q17：P3 不做语音朗读，只看文字

## 边界 / 红线
1. AI 只有建议权，无任何状态变更权；解锁/过关/阈值只能由规则引擎执行
2. 每个服务商 key 各自进 keychain，永不进 SwiftData/日志/导出包
3. 视频未经裁切与确认不出端；纯文字问题永不附带视频
4. 不发明教材外课程；拿不准必须声明能力边界

## 不做
- 自研 TTS（P3 不做朗读）、账号云同步、双视频并排
- 实时 AI 角标（M6 已定）、链失败中间过程弹窗
- P3 不做 M6 视觉手型检测本身，只做"视频发给多模态模型答疑"通道
