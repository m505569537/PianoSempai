# PianoSempai · 产品需求文档（Grill 决策全集）

> 状态：Phase 0-7 Grill 已完成，待用户评审 → Stitch UI
> Grill 日期：2026-09-17
> 项目代号：piano-sempai
> 产品定位：纯自用钢琴自学陪练 app（暂不考虑商业化）

---

## 0. 项目背景与用户画像

- 用户弹琴 2 年，自学，自评"不得其法、无法提升"。疑似典型"以曲代功"：两年主要啃曲子，基本功（音阶/琶音/哈农/读谱速度）没有系统推进。
- 设备：特伦斯 V70 折叠重锤电钢琴，**蓝牙 MIDI 已确认可用**（CoreMIDI BLE MIDI），USB-MIDI 待回家看机身 USB-B 口；单延音踏板（CC64）。
- 录像：iPhone 16 Pro（最新 iOS，日常）+ Nikon Zf（月度正式录像），有支架。
- 时间：每周 3 次、每次 30 分钟，偶尔 45 分钟；每周时间不固定。
- 谱面：五线谱、简谱都学过；现有谱子以 PDF 为主；哈农学过一点点。
- 曲趣：古典 + 日式轻音乐（久石让/坂本龙一/吉卜力类）。
- 产品诉求：完整系统课程、录音录像记录、AI 答疑、纠错、温柔型鞭策。

### 核心设计命题
app 要敢当"坏人"（基本功任务不能跳过、硬门禁防止自我放行），但语气温柔，不搞 guilt trip。速度决策由数据做，不由心急做。

## 2. 模块规格与已确认决策

### M1 MIDI 中枢

**连接管理**
- 底层 CoreMIDI，代码通过 orchetect/SwiftMIDI（MIT）封装层使用，不裸写 CoreMIDI。
- 首次连接向导：发现设备 → 选 V70 → 弹两音验证信号 → 完成。之后启动自动回连，会话内断线自动重连。
- 独立连接诊断页：设备状态、实时事件流（音高/力度/时间戳）、踏板事件、事件计数器。

**采集字段**
- Note On/Off（音高、力度）、CC64 延音踏板（单踏板）；soft/sostenuto 有则记录。
- 全通道记录落盘，默认按通道 1 分析；program change/pitch bend 记录但不依赖。
- BLE 丢包兜底：Note On velocity=0 视为 Note Off + 超长音超时截断；异常音标记"可疑事件"，禁止静默修正。

**时钟同步**
- CoreMIDI 与 AVFoundation 摄像头帧共用 hostTime 时钟域，会话开始打共同锚点，MIDI/视频毫秒级对齐，无需后期对轨。
- BLE 恒定 ~10-20ms 延迟：不影响音间间隔测量；判分容差按分级设置（如节奏 ±50ms 内不算错），不假装亚毫秒精度。

**落盘**
- 每条 take：原始 MIDI 事件流（永不加工、只追加）+ 可选视频附件 + 元数据 JSON。
- 全部本地沙盒；iCloud 仅同步元数据和 MIDI（小文件），视频默认不同步（设置页有手动开关）。

**中断边界**
- 蓝牙断线：自动暂停计时与判分，已弹部分保留，重连断点继续，中断期空白不判漏弹。
- app 退后台/锁屏：MIDI 采集停止（iOS 限制不硬抗），take 正常收尾保存；会话中默认阻止自动锁屏。

**已确认 Q**
- Q1=A：未连琴允许"自由弹奏"模式（录像/MIDI 照常存档，明确标记无判分分析）。
- Q2：单踏板（CC64 延音）。
- Q3=A：节拍器 iPhone 出声（可耳机），节拍音不进 take 数据。
- Q4：P1 一次铺好录像+MIDI 同步锚点地基（录像当时为可选全程；M4 阶段已修订为按需录像，见下）。

**开工前实机验证（用户回家做）**
1. 机身有无方形 USB-B 口。
2. iPhone 装 MIDI Wrench 或用库乐队，蓝牙连 V70 弹音验证信号。

### M2 乐谱与曲库

**导入**
- 格式：MusicXML（.xml/.mxl）主格式 + MuseScore（.mscz/.mscx，依赖渲染库解析能力，spike 验证）；标准 .mid 可导入生成简易谱面。
- 入口：Files 选择器、iCloud 文件夹自动扫描、分享面板"拷贝到 PianoSempai"。
- 导入即解析校验，失败明确报错，绝不静默收进库；成功后缓存渲染产物与规范化内部模型。

**渲染与跟进**
- P1 只做五线谱（简谱层后置，不阻塞）。
- 弹奏时光标按小节/音符跟进；P1 用简单 MIDI 匹配，M5 完成后升级为容错对齐（错音也不丢光标，支持停顿/回头补弹）。
- 支持指法编号（1-5）、段落 A/B/C 标记、小节号、循环区间框选、速度/调号显示、练习时自动滚动。

**曲库三区**
1. 训练教材：拜厄/哈农/车尔尼，按书→课号结构化，供 M3 引用。
2. 奖励曲库：自行导入的日音/流行等，按作曲家/难度/状态筛。
3. 全部导入：文件管理（删除/重命名/换分区）。
- 曲目状态：未开始 / 练习中（当前段落、速度）/ 已拿下（可复习）；难度按定级修正，按最近 take 数据说话，不搞自我感觉式"已掌握"。

**与练习关系**
- 曲谱 1 : N take；分段区间保存在曲目上（下次直接回到"上次崩在 17-24 小节"）。
- 分了左右手声部的谱支持分手练习/分手监听；不分轨的谱该能力灰显并说明原因。

**已确认 Q**
- Q1=A：不做 AI 猜分轨。分轨检测：有则支持分手，无则标记"单声部谱"。
- Q2=B：现有谱以 PDF 为主。**PDF 不做 OMR**：PDF 只进资料库查看；认真练的曲子需用 Mac 端 MuseScore/Audiveris（开源 OMR）转 MusicXML，或找现成工程文件。app 内放"如何获取可练谱"指引页，转换工具不进 P1。
- Q3：P1 不做简谱。
- Q4：教材顺序由产品侧编排（拜厄全本约 106 条按编号、哈农前 20 条、车尔尼 599→849），定级后决定插入点与跳过项。

**版权红线**
- 内置只放公版（拜厄/哈农/车尔尼，谱源 Mutopia/IMSLP 或 MuseScore 导出），目录由产品编排。
- 久石让/坂本龙一等非公有谱全部用户手动导入，app 不提供任何盗版下载入口。

### M3 课程引擎（app 的脑子）

**内容来源铁律（红线）**
- 教材骨架是开发期人工编排的结构化"课程数据"：每条练习带技术目标（五指位置/音阶穿跨指/阿尔贝蒂低音…）、前置条件、参考速度、过关标准。用户审阅后成为教学宪法。
- AI 只能在宪法内：解释定级、生成会话任务、解释错误、推荐加练；禁止自创教材条目或修改过关标准。

**入学定级（首次启动，约 20 分钟，三段式）**
1. 自备一首最拿手的曲子弹一遍（真实上限）。
2. 视奏一条没见过的小片段（即时读谱，自学党最易藏拙维度）。
3. 技术探针：C/G/F 大调音阶、分手+合手、哈农第 1 条慢速。
- 产出：六维雷达（音准/节奏/连续性/速度/读谱/双手协同）+ 路线插入点（例："拜厄从第 45 条进，哈农第 1 条，车尔尼暂不开始"）。
- 含 2 分钟个人力度校准（正常/强/弱三档各弹几个音），M5 力度分析只用相对值。
- 手型维度 P4 视觉上线后回填。

**路线结构**
- 主干：拜厄 → 车尔尼 599 → 849；哈农并行贯穿（前 20 条逐步解锁）；音阶/琶音随课插入。
- 条目状态：未解锁 / 在练 / 过关（达标 take）/ 复习池（间隔重弹防回生）。
- 奖励曲独立一条线，选曲自由（见 Q4）。

**会话任务生成（适配不固定时间）**
- 不排固定课表，按每次会话生成：热身（哈农/音阶 8-12 分钟）→ 主菜（当前课程分段，段由 M5 热点决定）→ 奖励曲（可选）。
- 开练前选 15/30/45 分钟，按时长裁剪。
- 周目标弹性区间 3-5 次，不预设星期几。
- 断练回归：先测复习池旧条目决定降速量，禁止假装没断过。

**过关与升降**
- 过关 = 连续 2 次 take 达到错音率/节奏偏差/目标速度阈值（阈值在课程数据内公开可查，非黑箱）。
- 连续不过：引擎承认铺垫不足，回退指定先修条目或插针对性练习，不许死磕。
- 手动强开口存在（见 Phase 6 高风险边界）。

**已确认 Q**
- Q1：真实投入下限 = 每周 3 次 × 30 分钟，偶尔 45。
- Q2=A：硬门禁 + 手动强开（二次确认+原因标签+月报留痕）。
- Q3：同意 20 分钟三段式定级。
- Q4=A：奖励曲自由选；app 分析导入曲的技术点并标"现在能弹/偏难/远超当前"，偏难曲的难点段落自动混进热身铺路，但不阻止弹。

### M4 练习会话

**会话结构**
- 今日卡片：时长选择 → 三段任务（热身/主菜/奖励曲）各带预计分钟；热身可跳过但连续跳过进月报，不骂但让你看见。
- 统一练习循环：选段 →（可选听示范/节拍器）→ 分段循环 → take 全量报告 → 升速 or 重来。

**分段循环（最高频界面）**
- 手动框小节，或一键"只练错误热点"（M5 挑上次错音集中的 2-4 小节）。
- 三种循环模式：连续循环（弹错不停）/ 错音即停（回段首，慢速精磨）/ 等待正确音（弹对才走，视奏新段）。
- 目标：循环 3/5/10 遍或 5 分钟；达标自动一次"完整收尾遍"。
- 变速阶梯：默认参考速度 60-70% 起，连续两遍达标自动 +5 BPM；弹崩自动 -5，禁止硬冲。

**分手/合手**：分声部谱可选 RH/LH/双手，任务可指定（如 LH×3→双手×3）；单声部谱灰显。

**节拍器**：iPhone 出声，拍号重音，4 拍预备拍；可选渐快模式（默认关）。

**示范播放（Q2=A）**：走 MIDI 回传 V70 琴内出声为主。

**会话 UI**：谱面为主+光标；顶部连接状态/当前任务/计时；底部速度/循环/分手/节拍器四常驻控件；一键暂停（断线自动暂停）；会话中"问 Neko"带当前段落直接进 M7。
- 首次会话弹一次 iOS 专注模式引导提示，不自动改系统设置（Q4）。

**录像策略（M1 Q4 的修订，用户纠正）**
- 日常练习**只采 MIDI，不录像**：手机放琴谱架位正对自己，专心看谱。
- 录像是独立的按需事件：
  1. "录给 AI 看"模式：手机移到侧拍支架 → 机位校准向导 → 录片段/整条 → 与该段 MIDI 自动配对，录完归位。M6 只在此类录像上工作。
  2. 月度 Zf：事后相册导入挂曲目时间线。
- 数据模型：会话必有 MIDI take；视频是挂在 take/片段上的可选附件，默认无。

**边界**
- 自由弹奏不打分不影响课程。
- 时间到没练完：正常保存，不制造欠账焦虑，下次重新生成。
- 同日第二次开 app：默认短会话建议（热身可缩短），防突击伤手。

**已确认 Q**
- Q1：机位矛盾由"按需录像"化解（见上），日常谱架位、手型侧拍位两套装机引导。
- Q3：新段首次默认连续循环+错误高亮（建立完整印象），精磨阶段才切错音即停。

### M5 MIDI 纠错分析（裁判模块）

**对齐**
- 离线对齐（弹后分析）：动态规划 note matching，算法对标 sildater/parangonar（Apache-2，林茨大学），Swift 重写；开发期用 Python parangonar 跑同一批测试 MIDI 对拍，输出一致才验收。
- 在线跟进：容错匹配，错音/漏音/重复/停顿/回头补弹不丢光标。
- 踏板进判分：CC64 踩着时琴键抬起不算音结束，否则误判漏音。

**六维判分（每 take 出全量报告，分区折叠：概览/错音/节奏/力度…，立即可见、永久留存、随时回看）**
1. 音高：错音/漏音/多弹，定位小节与节拍。
2. 节奏：逐音时间偏差分布，标抢拍/拖拍倾向。
3. 速度稳定性：瞬时 tempo 曲线、渐慢抢跑、达标对比。
4. 力度：velocity 均匀度、左右手力度差、旋律/伴奏层级（基于个人校准曲线，只做相对比较）。
5. 连续性：停顿次数与位置、卡顿热点（治"一录音就崩"）。
6. 分手统计：分声部谱左右手分别出分。

**热点与趋势**
- 小节级热力图，一键喂 M4"只练热点"。
- 同曲多 take 各维度曲线，区分真进步与感觉良好。

**诚实边界（红线）**
- 容差分级写进课程数据（入门宽、进阶严）。
- 自由弹奏无参考谱：不出对错分，只给统计（时长/力度分布/音域）。
- 对齐置信度低时报告明示"没对上，判分仅供参考"，禁止硬给结论。
- 可标"疑似谱面错误"：该点判分忽略并记录；同曲多处标记时曲库页提示换源。

**门禁联动**：过关阈值直接消费本模块错音率/节奏偏差/速度数据；阈值公开，随时可查"差多少过关"。

**评分呈现（Q3）**：弱总分、强维度；四维雷达+各维度分明示，总分仅用于进步曲线，不当过关依据。

**已确认 Q**
- Q1：全量报告直接贴出（用户自选当下看或以后翻），不做"先一句话总结"的人为闸门。
- Q2=A：弹奏中零打断，仅光标跟进+错误轻标色，弹完才分析。
- Q4：2 分钟个人力度校准放进定级流程。

### M6 视觉手型（P4，助教不是裁判）

**触发**：仅在主动"录给 AI 看"会话中运行；日常镜头不工作。端上推理（MediaPipe HandLandmarker 官方 iOS SDK，Apache-2），视频不出端。

**机位校准向导（用户不需要背机位规则）**
- 实时预览叠加引导框：双手入框、21 关键点骨架实时画出、琴键前沿参照线识别到才亮绿灯。
- 角度太偏/手出画/距离不对：红字提示怎么挪；10 秒自检报告（如"右手清晰，左手遮挡 60%"），用户接受才录。
- 默认推荐位：右侧、略高于键面、斜俯 30-45°；不强制，换边录左手时向导同样校验。

**检测项**
- 可靠判：折指（第一关节塌陷角）、手腕过高/过低/僵硬、手掌趴键、明显张紧异常。
- 粗粒度：指法明显异常（不做逐音指法裁判，手→键坐标映射侧拍误差大）。
- 双手交叉/遮挡：直接声明"没看清"，不硬判。
- 所有结果带置信度，低置信不显示为错误；报告"有效观测时长"。

**联动**：手型问题进 M3 热身建议备注（备注来自课程数据，非 AI 编造）；参与定级（P4 回填）；**永不进入过关门禁**。

**安全边界（M8 删除老师模块后的修订）**
- 永久明示单摄死角：手腕绝对高度、小臂发力、肩部紧张看不见。
- 不宣称 AI 可替代老师；极端姿势才升级休息提示；用户自述疼痛时固定文案建议停止练习并线下就医，不做任何医疗诊断/康复建议。

**已确认 Q**
- Q1=A：录后回看叠加标注为主（回放画面上画骨架+问题点，定位到秒）；不做实时角标（眼睛离键本身破坏手型）。
- Q3：要手型趋势（如"本月折指率 30%→12%"）。
- Q4：排序维持 P3 答疑在前、P4 视觉在后。

### M7 AI 助教

**三个入口**
1. 会话中"问 Neko"：自动带曲目/小节区间/刚才 take 分析。
2. 报告页：从某条具体错音/节奏问题发起。
3. 全局自由问答：乐理/指法/练法，带课程进度与历史 take 摘要。

**上下文包（本地组装）**
- 乐谱片段（MusicXML 截取）+ MIDI 分析结论 + 可选视频片段（仅主动录像 take）+ 定级画像与该曲练习史。
- 回答必须引用数据（第几次 take、第几小节、偏差多少 ms），禁止"多练就好"式空谈。

**模型（已确认用火山方舟，复用用户现有 key）**
- 文字/数据分析：doubao-seed-2.0-pro 类主力模型。
- 视频手型答疑：方舟豆包视觉理解模型（具体在售版本号 P3 开工时定，不写死）。
- 注意：现有 Hermes base_url 是 /api/coding（代码套餐入口），视觉模型大概率走标准 /api/v3，可能需同账号另开 key——**P3 开工半小时验证项**。

**权限红线**
- AI 只有建议权：解锁/过关/阈值变更只能由 M3 规则引擎执行；AI 可建议"回退拜厄第 40 条"，按钮用户点，状态变更留痕。
- 不能发明教材外课程。
- 拿不准明说并声明能力边界（已删除"去问真人老师"导流）。

**视频与隐私**
- 不整段上传：按提问小节区间自动裁切对应片段（hostTime 锚点对齐）；上传前弹确认，明示"将发送 X 秒视频到火山方舟"。
- key 存 keychain；纯 MIDI/文字问题不传视频；离线时文字问题本地组 prompt 降级，视频问题排队等网络。

**对话资产**：问答沉淀为可搜索"练琴笔记"，好解答可钉到曲目；月报从此处+take 数据自动起草，用户改后存档。

**主动性（Q2=A）**：按需回答为主 + 每周日晚一条合并通知（本周观察 + 下周一个小建议），每周最多一条，不啰嗦。

**已确认 Q**
- Q3：P3 文字+谱面标注，语音朗读用 iOS 系统 TTS 兜底，不做自研 TTS。
- Q4：中文答疑，曲谱术语保留原文（legato/arpège 等不硬翻）。

### M8 Take 档案与月度校准

**Take 结构**：曲目+任务类型、原始 MIDI、M5 分析（含置信度）、速度/时长、可选视频附件、日期；自由弹奏单独标记。本地存储，按曲目/日期/分数回看。

**时间线与对比**
- 曲目详情：全部 take + 维度趋势曲线；任意两条 take 对比（分数、热点变化）。
- "一个月前的我"证据流：月报自动挑进步最大对比。
- Q4：P5 做数据对比+单视频切换，不做双视频并排（iPhone 屏小，以后 iPad 再说）。

**Zf 月度录像**
- 相册导入，手动挂曲目与日期；无 MIDI 分析。
- 定位（老师模块撤除后）：纯个人高质量表演存档 + 月报前后对比证据，不导出给任何人。
- 引导固定机位、完整弹代表曲 1-2 首。月度录像永不自动清理。

**月报（每月 1 号生成）**
- 练习次数/总时长（对照 3×30 基线）、过关与卡关条目、各技术维度变化、手型趋势（P4 后）、硬开门禁手动强开记录与后续结果、下月建议。
- AI 起草，用户改，存本地。月报是当时快照，算法升级后不重算已出月报。

**老师模块：不做**（用户 Q3 决策）。不做校准包导出、上课记录、问题清单、找老师提醒。

**数据生命周期与导出**
- 视频：每曲保留最近 8 条，超出自动清理（MIDI/报告永久保留），Zf 月度录像永留；规则在设置页可见可改，不逐个发清理通知。
- "录给 AI 看"的视频保存时同时写一份进系统相册，想永久留的用户自行在相册保留。
- P1 即提供"导出我的全部数据"：曲谱+MIDI+分析+元数据打 zip（视频可选含）。换手机/重装靠 zip 恢复进度，不做账号同步。
- 分析算法升级：原始 MIDI 永久保留，用新算法统一重算历史 take 与趋势曲线（保证可比性），已发月报不动。

### M9 温柔鞭策

**出勤**：有效练习 = 有 MIDI、≥10 分钟的会话（任务练习与自由弹奏都计，自由弹奏单独图标不混课程数据）。
- streak 按周算：周目标 3 次，本周达标亮灯；连续达标周数正向显示，断了数字停止、历史最佳保留，不做灰色叉号/清零焦虑。

**提醒（本地通知，全可关）**
- 数据积累 2-3 周前：默认预设计划工作日 20:30、周末 14:00（首次可改）。
- 之后智能提议：按历史常练时段提前 15 分钟问"要不要弹 30 分钟？"。
- 本周未达标：周末最多提醒一次（"还差一次，10 分钟也算数"），不连发。
- 连续 7 天没练：只发一条"回来从复习池旧条目开始，不用从头补"，之后不再催。
- 周一起始。

**正反馈**：过关/解锁/连续达标周轻庆祝（无撒花轰炸）；月报进步证据为主反馈。
- M7 每周观察与鞭策合并为周日晚一条通知。
- Hermes cron 外部催练：P5 不做（本地通知先用一阵，真不够再加）。

## 3. Phase 6 边界总账

### 明确不做（任何阶段不复活）
- 不做安卓、不做 iPad 专版（兼容但不优化）
- 不做账号体系、服务端、社交、商城、曲库市场、约课/老师模块
- 不做麦克风音频识别；不做内置音源/发声（示范走琴、节拍器走 iPhone 除外）
- 不做瀑布流跟灯、OMR（PDF 转谱）、AI 猜分轨、盗版谱下载入口
- 不做实时错音打断、自研 TTS、双视频并排、云端视频备份

### 六条核心红线
1. 课程只许挂靠成熟教材（拜厄/哈农/车尔尼），AI 无锚点自创教学体系=禁止。
2. 分析没把握就明说（对齐低置信、手型没看清），禁止编造结论。
3. AI 只有建议权；课程状态只由 M3 规则引擎消费 M5 硬数据写入。
4. 视频镜头不常开；上传必经区间裁切+确认弹框+服务商明示（火山方舟）。
5. 手型永远是助教：不进门禁，永久声明单摄死角。
6. 产品性格：当坏人（热身不静默跳过、硬门禁）但语气温柔，不搞 guilt trip。

### 高风险机制边界
1. **硬门禁强开**：二次确认 + 原因标签（太难/想弹/其他）+ 月报留痕（次数与后续结果）；不限次数（自用无家长锁）。
2. **云端视频**：仅火山方舟、仅自己的 key（keychain）、仅提问区间裁切、上传前确认；纯文字/MIDI 问题绝不带视频。
3. **手型误判**：低置信不展示为错误；报告有效观测时长；"这条判错了"反馈本地留存供调规则。
4. **谱面错误**：标"疑似谱错"忽略该点判分；多处标记提示换源。
5. **BLE 丢包**：velocity=0 + 超时截断双兜底，可疑事件显式标记。
6. **健康边界**：极端姿势提示休息；疼痛自述→固定文案建议停止+线下就医，不做医疗建议。
7. **断练回归**：只陈述事实+复习池低风险重启，禁止"落后 N 课"施压文案。

## 4. Phase 7 技术架构

### 数据流主干
```
SwiftMIDI 收事件 → 会话引擎打 hostTime 锚点 → 原始事件流落盘（只追加）
                                   ↓
乐谱模型 ← 对齐引擎（在线光标 / 离线报告）→ M5 分析结果落盘
                                   ↓
M3 课程引擎（只读分析）→ 规则判定过关/加练/回退 → 写课程状态（唯一写手）
                                   ↓
M7 AI 助教（只读：谱片段+MIDI 分析+可选裁切视频）→ 建议，不写状态
M6 视觉（仅主动录像）→ 手型观测落盘 → 只进建议/趋势，不进门禁
```
**判分（M5）/ 拍板（M3）/ 出主意（M7、M6）三者强制隔离**，分析 bug 与 AI 幻觉无法直接篡改课程进度。

### 数据归属
- M2 拥有乐谱模型；M3 拥有课程定义数据与课程状态；M4 拥有会话生命周期。
- 原始 MIDI 只追加永不回写；分析结果可随算法升级重算；视频是 take 的可选附件非独立实体；M9 只消费不反向影响课程。

### 技术分层
- UI：SwiftUI，5 tab（今日 / 曲库 / 练习室-进行中与最近继续 / 档案 / 我的）+ 全屏练习室 + 全局"问 Neko"悬浮入口。
- 存储：SwiftData（iOS 17+，用户 iPhone 16 Pro 最新系统，无版本压力）存曲目/课程/take 元数据/问答笔记；MIDI 事件流与视频存沙盒文件，DB 只存路径。
- 领域层纯 Swift、不依赖 UI、可单测：课程规则引擎、对齐判分（parangonar 对拍）、手型规则。判分逻辑必须能用测试 MIDI 文件跑 CI。
- 基建层：SwiftMIDI、乐谱渲染库、MediaPipe、AVFoundation、火山方舟 API（唯一网络出口，仅 M7）。
- 零服务端。

### 开工前三个验证
1. **乐谱 spike（P1 第一天，一天出结论）**：swift-sheet-music 渲染质量 + .mscz 解析 + 光标跟进；失败立刻切 OSMD WKWebView。
2. **方舟视觉验证（P3 开工，半小时）**：/api/v3 入口、现有 key 可用性、视觉模型视频输入格式。
3. **V70 实机（用户回家，30 秒）**：USB-B 口有无 + GarageBand/MIDI Wrench 蓝牙弹音测试。

### 分期路线（技术分期，愿景不缩水）
- **P1 地基+定级**：M1 中枢（含按需录像与同步锚点）、M4 最小会话、M2 导入渲染（spike 定渲染库）、三段式定级、take 存储、全量数据导出。
- **P2 课程+裁判**：M3 课程引擎与每日任务（课程数据人工编排）、M5 Swift 对齐+六维分析+全量报告、硬门禁。
- **P3 AI 助教**：M7 火山方舟多模态问答、上下文包、每周观察、月报草稿。
- **P4 视觉助教**：M6 机位向导、MediaPipe 检测、回看叠加标注、手型趋势。
- **P5 档案与鞭策**：M8 同曲对比/Zf 导入/月报、M9 日历智能提醒。
