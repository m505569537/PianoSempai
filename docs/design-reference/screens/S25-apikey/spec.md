## 用途一句话

配置一条「多服务商 × 每商多模型」的有序故障转移链；提问时按顺序尝试，任一可用即工作，全链失败才报错；每个 Key 独立存钥匙串。

## 核心架构（用户原话锁定，勿改）

「模型接入应该要支持接入多个服务商，然后每个服务商下面允许选择多个模型，然后在实际使用过程中，你依次调用，有一个能够调用得通，那么就正常工作了。」

- 只配一条链，链上全部是多模态模型；纯文字问题走同一条链但不带附件（Q2，无独立文本链）。
- 静默故障转移，链失败中途不弹窗；粘住上次成功模型，定时试探高优先级恢复（Q5/Q6）。

## 服务商行展开（点行进入该商配置）

- 该服务商下的模型列表（可多个，每个模型 id + 单独状态点 + 删除）。
- 该服务商的 API Key：独立钥匙串条目，掩码末 4 位、眼睛显隐（30s 回掩码）、替换、删除。
- 服务商预设模板（火山方舟/百炼/DeepSeek 等带默认 endpoint）+ OpenAI 兼容自定义（填 baseURL）。
- Key 保存即做一次最小请求校验，错误显示原始码（401/ModelNotOpen/网络），不吞错。
- 单个服务商删除：二次确认 sheet，默认焦点取消；同时清该商钥匙串条目。

## 交互态（视觉）

- 全链失败：顶部状态卡变红「全部服务商暂不可用」，但不中途打断正在进行的提问（只在发起时判定）。
- 拖动排序：行抬起投影，落位即存优先级。
- 链路正常但当前是降级命中（首选挂、备用生效）：状态卡如实写「当前使用：DeepSeek」，首选行点红，不谎称首选。

## 数据/行为约束

- 连接态/链路由本地组件维护；Key 沿用并扩展 `APIKeyStore`（每服务商独立 account 名，互不串）。
- 故障转移诊断需记录实际命中模型与每跳失败原因（供「诊断记录」展示）。
- 不写死任何模型 id 在 App；模型版本全部此页可配。

## 红线落点

- Key 永不进 SwiftData/日志/导出/备份，内存外只在 Keychain（凭据铁律，沿用 APIKeyStore）。
- 故障转移静默，全链失败才报错；不向链中途弹「已切换服务商」打扰（Q6）。
- 视频不确认不出端；确认弹窗显示链路实际服务商名（见 S18b）。
- AI 只有建议权，服务商链配置本身由用户操作，无「自动添加服务商」。
